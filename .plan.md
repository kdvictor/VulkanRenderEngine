# Migration Plan: C-style Vulkan API to C++ vulkan.hpp

## Overview
Migrate VulkanEngine from C-style Vulkan API (`vulkan/vulkan.h`) to C++ API (`vulkan/vulkan.hpp`) for better type safety, RAII resource management, and cleaner code.

## Goals
1. Replace all C-style Vulkan types with C++ equivalents (e.g., `VkInstance` → `vk::Instance`)
2. Use C++ exception handling instead of manual error checking
3. Implement RAII with `vk::Unique*` handles for automatic resource cleanup
4. Modernize code with C++ idioms while maintaining the same functionality

## Migration Strategy

### Phase 1: Header File Changes
**File: `vulkanEngine/include/vulkan_engine.h`**

Changes:
1. Replace `#include <vulkan/vulkan.h>` with `#include <vulkan/vulkan.hpp>`
2. Replace all C types with C++ equivalents:
   - `VkInstance` → `vk::UniqueInstance`
   - `VkPhysicalDevice` → `vk::PhysicalDevice` (no unique, not owned)
   - `VkDevice` → `vk::UniqueDevice`
   - `VkQueue` → `vk::Queue` (no unique, retrieved from device)
   - `VkSurfaceKHR` → `vk::UniqueSurfaceKHR`
   - `VkSwapchainKHR` → `vk::UniqueSwapchainKHR`
   - `VkFormat` → `vk::Format`
   - `VkExtent2D` → `vk::Extent2D`
   - `VkRenderPass` → `vk::UniqueRenderPass`
   - `VkCommandPool` → `vk::UniqueCommandPool`
   - `VkCommandBuffer` → `vk::CommandBuffer`
   - `VkSemaphore` → `vk::UniqueSemaphore`
   - `VkFence` → `vk::UniqueFence`
3. Replace raw pointers with `std::vector`:
   - `VkImage* m_swapchainImages` → `std::vector<vk::Image> m_swapchainImages`
   - `VkImageView* m_swapchainImageViews` → `std::vector<vk::UniqueImageView> m_swapchainImageViews`
   - `VkFramebuffer* m_framebuffers` → `std::vector<vk::UniqueFramebuffer> m_framebuffers`
4. Remove `m_swapchainImageCount` (use vector.size() instead)
5. Update method signatures where needed

### Phase 2: Implementation File Changes
**File: `vulkanEngine/src/vulkan_engine.cpp`**

#### Constructor/Destructor
- Constructor: No changes needed
- Destructor: Simplify dramatically - RAII handles cleanup automatically
  - Remove all manual `vkDestroy*()` calls
  - Remove all `delete[]` calls for arrays
  - Just call `cleanup()` which will wait for device idle

#### `createInstance()`
**Before:**
```cpp
VkApplicationInfo appInfo{};
appInfo.sType = VK_STRUCTURE_TYPE_APPLICATION_INFO;
// ... set fields
VkInstanceCreateInfo createInfo{};
createInfo.sType = VK_STRUCTURE_TYPE_INSTANCE_CREATE_INFO;
// ... set fields
VkResult res = vkCreateInstance(&createInfo, nullptr, &m_instance);
if (res != VK_SUCCESS) return false;
```

**After:**
```cpp
vk::ApplicationInfo appInfo{
    "SimpleCAD", VK_MAKE_VERSION(1,0,0),
    "No Engine", VK_MAKE_VERSION(1,0,0),
    VK_API_VERSION_1_0
};
vk::InstanceCreateInfo createInfo{
    {}, &appInfo,
    static_cast<uint32_t>(layers.size()), layers.data(),
    static_cast<uint32_t>(extensions.size()), extensions.data()
};
try {
    m_instance = vk::createInstanceUnique(createInfo);
    return true;
} catch (vk::SystemError& err) {
    std::cerr << "vkCreateInstance failed: " << err.what() << "\n";
    return false;
}
```

#### `createSurface()`
**Changes:**
- Use `vk::Win32SurfaceCreateInfoKHR`
- Use `m_instance->createWin32SurfaceKHRUnique()`
- Exception handling instead of result checking

#### `pickPhysicalDevice()`
**Changes:**
- Use `m_instance->enumeratePhysicalDevices()`
- Returns `std::vector<vk::PhysicalDevice>` directly
- Use `physDev.getQueueFamilyProperties()` instead of two-step enumeration
- Use `physDev.getSurfaceSupportKHR()` for present support check

#### `createLogicalDevice()`
**Changes:**
- Use `vk::DeviceQueueCreateInfo` and `vk::DeviceCreateInfo`
- Use `m_physDev.createDeviceUnique()`
- Use `m_device->getQueue()` to retrieve queue

#### `createSwapchain()`
**Changes:**
- Use `m_physDev.getSurfaceCapabilitiesKHR()`
- Use `m_physDev.getSurfaceFormatsKHR()`
- Use `m_physDev.getSurfacePresentModesKHR()`
- Use `vk::SwapchainCreateInfoKHR` with proper initializers
- Use `m_device->createSwapchainKHRUnique()`
- Use `m_device->getSwapchainImagesKHR()` which returns vector directly

#### `createRenderPass()`
**Changes:**
- Use `vk::AttachmentDescription`, `vk::AttachmentReference`
- Use `vk::SubpassDescription`, `vk::SubpassDependency`
- Use `vk::RenderPassCreateInfo`
- Use `m_device->createRenderPassUnique()`

#### `createFramebuffers()`
**Changes:**
- Create image views: `m_device->createImageViewUnique()`
- Create framebuffers: `m_device->createFramebufferUnique()`
- Store in vectors, automatically managed

#### `createCommandPool()`
**Changes:**
- Use `vk::CommandPoolCreateInfo`
- Use `m_device->createCommandPoolUnique()`

#### `createCommandBuffer()`
**Changes:**
- Use `vk::CommandBufferAllocateInfo`
- Use `m_device->allocateCommandBuffers()` returns vector
- Take first element

#### `createSyncObjects()`
**Changes:**
- Use `vk::SemaphoreCreateInfo`, `vk::FenceCreateInfo`
- Use `m_device->createSemaphoreUnique()`, `m_device->createFenceUnique()`

#### `recordCommandBuffer()`
**Changes:**
- Use `vk::CommandBufferBeginInfo`
- Use `cmd.begin()`, `cmd.end()`
- Use `vk::RenderPassBeginInfo`
- Use `cmd.beginRenderPass()`, `cmd.endRenderPass()`
- Use `vk::ClearValue`

#### `renderLoop()`
**Changes:**
- Use `m_device->waitForFences()`, `m_device->resetFences()`
- Use `m_device->acquireNextImageKHR()` returns `std::pair<vk::Result, uint32_t>`
- Use `cmd.reset()`
- Use `vk::SubmitInfo` with proper structure
- Use `m_graphicsQueue.submit()`
- Use `vk::PresentInfoKHR`
- Use `m_graphicsQueue.presentKHR()`

#### `cleanup()`
**Simplified:**
```cpp
void VulkanEngine::cleanup()
{
    if (m_device) {
        m_device->waitIdle();
    }
    // All Unique handles automatically destroyed in reverse order
}
```

### Phase 3: Error Handling Strategy

Two approaches:

**Option A: Keep bool returns, catch exceptions internally**
```cpp
bool createInstance() {
    try {
        // C++ Vulkan code
        return true;
    } catch (vk::SystemError& err) {
        std::cerr << "Error: " << err.what() << "\n";
        return false;
    }
}
```

**Option B: Let exceptions propagate, change init() signature**
```cpp
void init(void* handle, uint32_t w, uint32_t h); // throws vk::SystemError
```

**Recommendation: Option A** - Maintains compatibility with existing main.cpp

### Phase 4: Testing Strategy

After each major change:
1. Compile and fix any compilation errors
2. Run the application
3. Verify window opens with blue background
4. Check for validation layer messages
5. Verify no memory leaks (RAII should handle this)

## Benefits After Migration

1. **Automatic Resource Management**: No manual destroy calls, no memory leaks
2. **Type Safety**: Strong typing prevents many errors
3. **Cleaner Code**: Less boilerplate, more readable
4. **Better Error Messages**: Exceptions include descriptive messages
5. **Modern C++**: Uses RAII, std::vector, exceptions

## Risks & Mitigation

**Risk**: Breaking existing functionality
**Mitigation**: Incremental migration, test after each function

**Risk**: Performance overhead from exceptions
**Mitigation**: Exceptions only during initialization, not in render loop hot path

**Risk**: Debugging might be harder with abstraction
**Mitigation**: Vulkan validation layers still work the same way
